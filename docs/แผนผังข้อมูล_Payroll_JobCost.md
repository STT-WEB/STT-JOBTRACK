## 1. ข่าวดี 3 ข้อ (เจอของที่คิดว่าไม่มี)

### ① Est. Budget กับ Sale Budget **มีคอลัมน์รออยู่แล้ว**
ไฟล์ `Jobcost Master/Dashboard 2026` แท็บแรก มีคอลัมน์ครบตามที่เบียร์ต้องการอยู่แล้ว:

```
ประเภทงาน | Job Code | ชื่องาน | ม.ค. … ธ.ค. | ยอดยกมา |
รวมค่าแรง STT | ค่าแรงผู้รับเหมา | Total Cost |
Est. Budget | Sale Budget | ส่วนต่าง Budget | % Cost/Budget | สถานะ
```

> **แต่ 5 คอลัมน์ขวาสุดยังว่างทั้งหมด** (Est. Budget / Sale Budget / ส่วนต่าง / % / สถานะ) — โครงพร้อม รอเติมข้อมูล

### ② ตัวเลข Budget กับ ยอดขาย **มีอยู่แล้วอีกไฟล์**
ไฟล์ `STT Jobcost Database-Payroll` มี 2 ตารางนี้อยู่:

| ตาราง | คอลัมน์ | จำนวนแถว | เอาไปใช้เป็น |
|---|---|---|---|
| Budget labour | `DocuNo` · `custName` · **`Budget labour`** | ~207 | **Est. Budget** (งบค่าแรง) |
| ยอดบิล | `DocuNo` · `custName` · **`SUM ของ billaftrDiscAmnt`** | ~207 | **Sale Budget** (ยอดขายหลังหักส่วนลด) |
| ค่าจ้างผู้รับเหมา | `JobCode` · `JobName` · `vendorname` · `Goodname` · `SUM ของ GoodAmnt` | ~249 | **ค่าแรงผู้รับเหมา** |

→ **ต่อ 3 ตารางนี้เข้า Master ด้วย Job Code ก็ได้ข้อ ④ ครบทันที** ไม่ต้องหาไฟล์ใหม่

### ③ สูตร Performance ที่เบียร์จำไม่ได้ — ถอดออกมาแล้ว
จากแท็บ `PERFORMANCE` ในไฟล์ Cal มกราคม 2569:

```
ชม.มาตรฐาน               208     (26 วัน × 8 ชม.)
− ชม.หยุดนักขัตฤกษ์        32
= ชม.มาตรฐานสุทธิ         176

% Performance = ชม.ปกติจาก Timesheet ÷ ชม.มาตรฐานสุทธิ × 100
ต้นทุน/ชม.จริง = (เงินเดือน + OT + สวัสดิการ) ÷ ชม.รวมทั้งหมด
```

ตรวจกับข้อมูลจริง 3 คนแล้ว ตรงทุกคน: `176/176 = 100` · `144/176 = 81.82` · `152/176 = 86.36`

> ⚠️ **แต่เจอจุดที่ต้องแก้:** ทั้ง 3 คนได้เกรด **A+ เท่ากันหมด** ทั้งที่ Performance ต่างกัน (100 / 81.82 / 86.36)
> แปลว่าเกรดตอนนี้คิดจากช่อง **"ชม.ขาด/ลาจริง"** (ทุกคน = 0) ไม่ได้คิดจาก %Performance
> **คนที่ทำงานแค่ 81.82% ก็ยังได้ A+** — ต้องเคาะเกณฑ์เกรดใหม่ (ดูข้อ 5)

### กติกาคำนวณจริง (ถอดจากแท็บ JOB_COST_DIRECT)

```
ชั่วโมงปกติ : ต้นทุน = (ยอดฐาน ÷ ชม.รวมที่ใช้หาร) × จำนวนชั่วโมง
              ตัวอย่างจริง 23,575.00 ÷ 184 × 8 = 1,025.00 ✓

ชั่วโมง OT  : ต้นทุน = OT Rate × Multiplier × จำนวนชั่วโมง
              ตัวอย่างจริง 83.33 × 1.5 × 2.5 = 312.50 ✓

พนักงานรายวัน : OT Rate = อัตรา/วัน ÷ 8   (600 ÷ 8 = 75.00 ✓)
พนักงานรายเดือน: OT Rate = เงินเดือน ÷ 30 ÷ 8
```

## 3. ⚠️ ความเสี่ยงใหญ่ที่เจอ — JOBTRACK เปลี่ยนคอลัมน์ 4 รอบในปีเดียว

ไฟล์ `JOBTRACK_Job_Log 2026` มีตาราง 4 ชุดที่คอลัมน์ **ไม่เหมือนกัน**:

| รุ่น | คอลัมน์ที่มี | หมายเหตุ |
|---|---|---|
| รุ่น 1 (พ.ค.) | Timestamp · วันที่ · เวลาเข้า/ออก · ชม.รวม · Job ID · Zone · แผนก · สถานะ · Process · ประเภทวันทำงาน · ประเภทชั่วโมง | มี `Zone` |
| รุ่น 2 (พ.ค.) | + `ชม.ปกติ HH:MM` · `ชม.OT HH:MM` · `ชม.ปกติ ทศนิยม` · `ชม.OT ทศนิยม` | เพิ่มชั่วโมงแยก |
| รุ่น 3–4 (ก.ค.) | ตัด Zone ออก · เพิ่ม **`ประเภทพนักงาน` · `รหัสรอบงาน` · `หมวด Process` · `รหัสงาน` · `ชื่องานย่อย` · `จำนวน Process` · `ชม.คิดค่าแรง`** | โครงที่ใช้อยู่ตอนนี้ |

**ผลกระทบ:** ถ้าระบบใหม่อ่านแบบตายตัว จะพังทันทีที่เจอข้อมูลเดือนเก่า

## 4. โครงงานที่ปรับใหม่ตามที่เบียร์แก้มา

```
① Data Payroll (จ่ายจริง)
   └─ + Dashboard ผู้บริหาร:  ยอด/เดือน · เพิ่ม-ลด · จำนวนคนที่จ่าย
                              · ยอดจ่ายเทียบกับที่บัญชีจ่ายออกจริง
② ตรวจเวลา 3 ทาง : Bplus (สแกนนิ้ว) ↔ JOBTRACK (จ๊อบ/process/ชั่วโมง) ↔ BP ที่จ่ายจริง
   └─ ไม่เกี่ยวกับ Budget/Estimate ในขั้นนี้   ← (แก้ตามที่เบียร์ทัก)
③ Performance พนักงาน Direct รายคน + สถิติรายปี
④ Cal Job Cost  : คิด Direct จากเวลา 2 ตัว → ต้องเท่ากับ Payroll จ่ายจริง
   └─ แล้วจึง Allocate ค่าแรงทางอ้อม (Indirect) เข้าจ๊อบที่เกิดในเดือนนั้น
⑤ Master จ๊อบ   : เริ่ม→ปิดจบ กี่วัน · ค่าแรงรายเดือน × ต้นทุนต่อจ๊อบ
                  · เทียบ Est. Budget + Sale Budget + ส่วนต่าง + % Cost/Budget
```

**ทุกตารางกรองได้เหมือน Excel** (พิมพ์กรอง / เลือกหลายค่า / เรียง / ล้าง / ส่งออก)
